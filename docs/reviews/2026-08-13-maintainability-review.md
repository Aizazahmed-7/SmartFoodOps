# Maintainability & Readability Review — 2026-08-13

> Scope: entire repository (7 libs, 6 services, tools, frontend, docs, build system) at the close of the W2 milestone.
> Method: 8 area reviewers under a SOLID/production-readiness lens; every finding challenged by a per-area skeptic against docs/adr/ and the repo's deliberate idioms; survivors synthesized and prioritized. 55 findings survived, 8 were rejected as cargo-cult or contradicting documented decisions.

## Overall assessment

This is an unusually disciplined codebase for its age: the hexagonal layering actually holds under grep, the ADR culture is real, the 478-test/100%-coverage bar is genuinely met, and the W2 idioms (Literal vocabularies, error-mapping tables, conftest channels) are visibly better than W1's — the team is improving as it goes. The dominant maintainability risk is not design quality but replication: platform machinery (internal HTTP conventions, service bootstrap, the Kafka consumer loop, the outbox DDL) exists as 4-6 hand copies with drift already observable — three shutdown-choreography shapes, two stale schema-registry defaults, an inventory consumer mis-applying the rollback protocol — and the documented target of 13 services doubles every copy. The second risk is that the stated system trails the built one: the front-door docs still describe a docs-only repo, CI enforces strictly less than the review process even though every promised gate passes green today, and several ops affordances (make chaos, compose --wait, /readyz) report success while doing nothing. Third, the frontend is exempt from every bar the backend enforces, despite owning money-adjacent protocol logic that has already produced review-caught bugs. Nearly all high-value fixes here are S-effort codifications of things that are already true or already promised in the repo's own docs and comments; the M-effort extractions should land before W3 multiplies the copy counts. Nothing requires a redesign — this is a pay-small-debts-now review, and the debts are unusually well itemized by the codebase itself.

## Themes (root causes appearing across areas)

### Platform machinery as N copies, with drift already started

Cross-service plumbing — internal HTTP header/retry conventions, the create_app bootstrap ceremony, the Kafka consumer loop, the outbox table DDL, and test harnesses — is copy-pasted 4-6x instead of living in libs/, violating repo-structure.md's own rule 2. This is not speculative DRY: drift is observable today (three shutdown-choreography shapes across main.py files, identity/catalog defaulting to the known-squatted 8081 registry port while three siblings say 8086, inventory's consumer copy silently discarding sibling batch work on a race, six diverging snapshot() builders in order's tests). With 13 services as the documented target, every remaining copy roughly doubles.

Member findings: *internal_headers() once, timeouts into Settings — the internal-call contract is 5 copies of folklore*; *Extract the bootstrap invariants into smartfood-api; leave lifespans per-service*; *Land EventConsumer + smartfood_kafka.testing before the saga-sweeper becomes copy #3*; *outbox_table() and stage_event() belong to smartfood-outbox, matching the idempotency_table precedent*; *Encode the insert-race upsert once in InventoryRepo — one copy already silently discards sibling work*; *Test-package consolidation through the sanctioned conftest channel*

### Comment-as-contract: closed vocabularies the type system never sees

The repo's own documented idiom is StrEnum/Literal + get_args-derived CHECKs, yet config mode flags (`outbox_mode: str = "off"  # poller | off`), auth roles, W1 restaurant/user statuses, edge-bff route modes, the order-status families (trapped in sqlalchemy-importing db.py so sandboxed workflow code degrades to bare strings), and every frontend error-code comparison are bare strings policed by comments. Typos boot cleanly and silently disable event publishing, mislabel the auth surface, or never match at runtime.

Member findings: *Close the typed-vocabulary gaps: config mode flags, roles, W1 statuses, edge-bff route modes*; *Move the order-status vocabulary into values.py — the sandbox-safe module the workflow rule already designates*; *Frontend consistency sweep: typed codes, correlatable errors, one quote hook, login return path*

### The stated system trails the built system

Docs and gates describe a different repo than the one that exists. README/ARCHITECTURE/repo-structure still say docs-only/design phase; local-dev.md names make targets, test tiers, tools, and lib modules that do not exist; repo-structure.md claims import-linter contracts are committed (none are); ci.yml runs less than the review process enforces even though pyright, the 100% coverage gate, and tsc all pass green today; /readyz is architecturally load-bearing and unimplemented; make chaos prints success while provably doing nothing. The repo already owns the honesty idioms ((W2)/(W3) markers, as-built annotations, source-scan tests) — they just were not applied everywhere.

Member findings: *Turn on the gates that already pass: coverage, pyright, import contracts, FE build*; *One as-built docs pass: the front doors describe a repo that no longer exists*; *Implement /readyz + compose healthchecks — the ALB/ECS commitment nobody built*; *Make the compose story honest: env interpolation, self-verifying chaos, restart policies*

### Wire shapes with two authors

Response and error bodies are built independently in multiple places: payment's decline body hand-rolled twice and persisted into idempotent replays without a request_id; order's 202 built once for storage and once for the fresh path; catalog/identity repeating per-route mapping blocks with message drift already visible; smartfood-auth's 401/403 riding smartfood-api's documented-as-discouraged fallback table; and the FE hand-mirroring DTOs against an OpenAPI doc that has no schemas for the money endpoints. Every one of these drifts silently because each author is self-consistent.

Member findings: *One author per wire error shape: payment declines, placement body, and the catalog/identity mapping blocks*; *Add response models to externally-routed surfaces — the merged OpenAPI is hollow exactly where the money is*

### The frontend is exempt from the backend's discipline

The backend holds a 100%-coverage, Literal-everywhere, one-envelope bar; the frontend has zero tests, zero lint, untyped wire vocabularies, duplicated quote logic that has already diverged (Cart re-pins menu_version, Checkout doesn't), four hand-rolled error banners, and a 273-line partner dashboard — while owning idempotency-key lifecycle, single-flight token refresh, and cart-merge logic that already produced two review-caught bugs in S8.

Member findings: *Stand up the FE unit harness for the money-adjacent protocol logic*; *Frontend consistency sweep: typed codes, correlatable errors, one quote hook, login return path*; *Extract PartnerMenu and make partner tabs addressable*; *Add response models to externally-routed surfaces — the merged OpenAPI is hollow exactly where the money is*
